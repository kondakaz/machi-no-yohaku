この実験の見方・操作ガイド

まずは予約でルートを変えてみる

「9:40の実演へ（リセット）」を押し、公園→病院のまま「この移動を予約する」。灰色の線が予約前、緑・青の破線が追加後の今後15分の予定です。再生すると、バスが道路を走り、停留所の人を迎えにいきます。実行中の区間や近い確定便がある場合、コースの変更はその後に反映されます。過去15分の走行実績は薄い実線で表示します。

右のスマホ画面で乗車地・目的地を選び、予約すると迎え予定と乗車状況が表示されます。「迎え・到着まで動かす」で時間が進み、待機中の名前が乗車時に消え、到着まで追えます。迎え時刻は現在の配車計算による目安で、追加の乗車で変わる場合があります。地図は京都風の架空の街です。細い生活道路は景観表示で、バスは設定された主要道路を走ります。

基本操作を1分で体験

  1. バスを動かす：「B 予定＋需要予測」とシード「42」のまま、「＋10分」を2回押して9:20へ進めます。「再生」なら自動で進み、もう一度押すと一時停止。速度は右のメニューで変えられます。
  2. 予定を変える：登録者の予定で、滞在中の佐藤さんの「あと30分」を押します。次の出発可能時刻が9:42から10:12に変わります。帰着期限は変わりません。運行を進め、後続の迎えや達成状況を見てください。
  3. 同じ条件で比べる：「A / B を最後まで比較」を押すと、AとBを同じシード・追加予約と予定変更なしで9時から12時まで計算し、結果を並べます。いま見ている地図の時刻と変更内容はそのままです。
  4. 別の需要で試す：シードを「1」に変えて比較すると、Bが必ず有利ではない例を見られます。「条件を再生成」でそのシードの運行を9時からやり直せます。A/Bの方式切り替えも運行と予定変更をリセットします。

時間を自由に見返す：時計の右のスライダーを動かすと、9:00〜12:00の任意の時刻へ1分単位で移動します。車両・待機者・達成状況・ログもその時刻に切り替わり、再生は一時停止します。予定変更は巻き戻しても保持されます。過去の時刻で新たに予定を変更した場合は、その時刻より後の変更を取り消して運行を再計算します。

画面の読み方

緑の円は今後30分の予測需要で、実際の乗客数ではありません。オレンジの人型アイコンはその場にいる未予約者。青い人型アイコンと名前は予約して迎えを待っている人で、乗車すると地図上の名前が消えます。バスの数字は「車両番号・乗車人数」です。「未予約者の移動」と運行ログで、実際の乗車・到着を追えます。

「あと30分」は滞在中に使えます。出発可能時刻まで10分以内、または次の迎えが確定済みの場合は変更を断ります。割り当てられない移動や期限内に終わらない予定も、成功として数えません。

比べたいのは「何人多く運べたか」と「そのために何km走ったか」。登録者の達成率も一緒に見てください。このデモのシード42では、登録者はA/Bとも5人達成、未予約者はAが0人・Bが4人、距離は109.8km・154.8kmです。距離増加も含めて効果を考える実験です。

実験の条件と簡易版の範囲

AもBも、停留所に来た時点で未予約者を確認し、運べる場合は受け入れます。Bだけが仮の期待需要を使って立ち寄ります。未来の発生時刻や、到着前の待機人数は配車に使いません。

結果は固定の道路と仮の需要から計算するもので、実地域での効果を保証しません。Bが必ず有利になる設定ではありません。比較ボタンは同じシード・追加予約と予定変更なしで最初からA/Bを実行します。

ブラウザ内で完結するHTML/JavaScript版です。AIによるコード作成支援を利用しています。需要予測は学習済みAIではなく仮定した分布です。

簡易配車：固定道路の最短経路と貪欲な割当を使います。全訪問・全車両をまとめて最適化する方式ではありません。各車の次の迎え1件を確定し、その先は仮計画にします。出発可能時刻と帰着期限をもとに次便を割り当て、10分以内の便の変更は拒否します。将来の全訪問を含めた厳密な挿入最適化は本格版の追加範囲です。
